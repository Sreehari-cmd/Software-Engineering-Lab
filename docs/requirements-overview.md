# Requirements Overview

This page is a short checklist based on the project's Software Requirements Specification (SRS). The SRS remains the main reference for detailed requirements.

## Functional requirements

| ID | Requirement |
|---|---|
| REQ-1 | Allow users to create an account and log in. |
| REQ-2 | Allow customers to search restaurants and food and add items to the cart. |
| REQ-3 | Display menu items, prices, and availability. |
| REQ-4 | Allow customers to add, remove, and change cart quantities. |
| REQ-5 | Show errors when required information is invalid or incomplete. |
| REQ-6 | Allow customers to place an order with a valid delivery address and checkout information. |
| REQ-7 | Support online payment and record payment status. |
| REQ-8 | Update order status through placed, accepted, preparing, out for delivery, and delivered; notify the customer. |
| REQ-9 | Allow customers to track orders, view order history, and rate completed orders. |
| REQ-10 | Allow restaurant staff to accept/update orders and delivery partners to update only their assigned deliveries. |

## Non-functional requirements

The SRS identifies performance, safety, security, and quality attributes as non-functional requirement areas. Refer to the approved SRS for their detailed statements and acceptance criteria.

## Main business roles

- Customer
- Restaurant staff
- Delivery partner

## Alignment note

Keep diagrams, prototype screens, implementation, and test cases consistent with the SRS. If a requirement changes, update the SRS and the related project tasks together.
